# 公开数据选择与验证边界

## 当前决定

沿用Spotify Basic Pitch 0.4.0作为模型基础，不因上传限制重换整个项目。先准备GuitarSet做吉他音频的诊断与流程评测；琵琶专项效果另用有权使用的独奏录音验证。目前未获得可核查的琵琶音频+逐音符配对数据。

## 已核查的来源

- 模型：https://github.com/spotify/basic-pitch ，Apache-2.0。
- GuitarSet官方仓库：https://github.com/marl/GuitarSet ，代码仓库MIT；官方数据发布https://zenodo.org/records/3371780 已确认音频与标注为CC BY 4.0，需保留作者署名和许可，注明处理改动。
- 数据说明：360段约30秒吉他录音，包含麦克风音频、分弦音频及JAMS格式的音符、音高轨迹、和弦、节拍标注。实现参考mirdata的GuitarSet loader。其LICENSE_INFO写作MIT，与官方数据记录的CC BY 4.0不一致；数据使用遵循官方记录，代码许可与数据许可分别列明。
- 官方仓库明确提示两处时序错误和重复音符等已知标注问题，不能默认全部标注没有误差。

## 重要诊断

Basic Pitch上游代码存在GuitarSet训练流水线。没有确认当前预训练模型的划分前，GuitarSet只能作为诊断数据，不能宣称“完全未见过的独立测试集”。也不能在同一测试集调阈值后把提升称为泛化提升。

mirdata GitHub上的小音频属于测试fixture。本次发现其中一份标注声明约32秒、音频实际只有2秒，而且包含MIDI音高120等被修改的测试数据，因此不拿它计算正式准确率，也不静默过滤异常后称为可靠评测。

## 网络状态

GitHub与Zenodo来源现可读取。此前出现的CONNECT 403在用户保存网络配置并环境更新后已解除。官方记录API已读取，确认版本1.1.0、CC BY 4.0及两个必要归档的校验值。归档下载和评测结果按实际运行记录单独报告。

## 下载与准备

只需官方记录中的 `audio_mono-mic.zip` 与 `annotation.zip`，不用下载六通道及其他音频变体。完整音频包可能较大，优先直接下载到服务器，不经过聊天附件传输。

mirdata公开loader中记录的档案MD5（用于核对官方文件，不是修改校验值）：

- audio_mono-mic.zip：275966d6610ac34999b58426beb119c3。
- annotation.zip：b39b78e63d3446f2e54ddb7a54df9b10。

保留HTTPS验证，下载后核对发布页和归档校验值；若不匹配，停止使用并检查版本。不要以代码仓库中的测试fixture代替完整档案。

解压后运行：

```bash
.venv/bin/python scripts/prepare_guitarset.py /path/to/audio_mono-mic /path/to/annotation --limit 12 --seed 2026
```

脚本在模型推理前固定12个样本，输出独立标注CSV及manifest，并记录异常样本，不按得分替换样本。初稿与人工校对分别评测，结果不能写成算法原创贡献或琵琶准确率。提交材料需保留来源引用与数据使用说明。

## 自动下载与批量运行

网络可用时，从仓库目录执行：

```bash
.venv/bin/python scripts/download_guitarset.py
.venv/bin/python scripts/prepare_guitarset.py var/datasets/guitarset/audio_mono-mic var/datasets/guitarset/annotation --limit 12 --seed 2026
.venv/bin/python scripts/batch_evaluate.py artifacts/guitarset/manifest.json
```

Windows将`.venv/bin/python`替换为`.venv\Scripts\python.exe`。官方下载脚本先读取发布记录中的许可与校验元数据，再下载两个归档；TLS和归档MD5校验保持启用。解压拒绝路径越界、符号链接和覆盖已有不同内容文件。脚本必须在实际网络恢复后执行成功，不能把本地安全性测试写成已下载官方数据。

批量脚本每次使用新结果目录，保存每段原始预测、音频/标注SHA256、模型版本、推理时间、逐段指标、汇总和失败原因。有失败或标注拒绝时标为incomplete并返回非零退出状态，不能只展示成功样本平均值而省略失败数。

已核查上游划分代码的默认比例为80%训练、10%验证，随机种子默认未指定。仅重新使用相同比例无法证明复现了已发布权重的真实划分，所以目前不声称独立测试集。
