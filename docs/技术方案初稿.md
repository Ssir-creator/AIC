# 谱易改：琵琶短录音转谱与纠谱

2026 AIC · 赛题2：AI+软件创新。2026年10月11日审核草稿；尚未套用官方模板，真实用户效果与独立标注待补。匿名材料不含学校、Logo或指导教师信息。

## 一、产品概述与定位

面向希望整理短录音、检查音符的琵琶学习者。项目将“生成音符初稿—对照原音校对—参考曲谱定位—乐谱草稿导出”连接为一条使用流程。

目标任务是帮助使用者定位并修正识别结果中的错音、漏音和时长，得到可继续制谱的草稿。有参考曲谱时，额外提示曲谱与识别结果之间的差异。差异可能来自演奏、模型识别或时间对齐，不能直接作为演奏评分。

作品简介（待定稿）：谱易改是一款面向琵琶学习者的短录音转谱与纠谱原型。系统基于开源Basic Pitch生成音符初稿，支持原音定位、音高与时长编辑、参考曲谱对照及MIDI/MusicXML草稿导出。针对自由速度片段，提供试验性的旋律序列自动定位，并保留模型初稿、人工修改及对齐来源。三段本人演奏的琵琶短录音已完成识别与界面验证，独立标注和用户效率验证尚待完成。

当前没有用户规模、教学提效或商业收入数据。场景需求是待真实访谈验证的假设，不以模型运行成功替代应用价值证明。

## 二、技术架构与选型

浏览器界面 → FastAPI接口 → ffmpeg音频解码 → Basic Pitch ONNX CPU推理 → 音符事件持久化 → 人工校对/参考定位 → MIDI、MusicXML与JSON导出。

|层次|功能与实现|
|---|---|
|输入层|0.2—60秒音频，20MB上限，解码为22.05kHz单声道；拒绝无效、过长或近静音输入|
|识别层|Spotify Basic Pitch 0.4.0官方ONNX CPU模型，未重新训练，推理并发受控|
|交互层|原音播放器、音符时间轴、模型/参考叠加、逐音符编辑、补音、删除和撤销|
|参考层|MIDI参考导入，时间缩放/平移，时序配对；单旋律序列自动定位为试验功能|
|记录层|本地项目、原始/当前音符、编辑版本、参考来源和对齐历史；重启可恢复|
|导出层|MIDI保持实际秒级音符；MusicXML按用户指定节拍生成草稿；JSON保存贡献与差异|

Python3.12、FastAPI、NumPy/SciPy、pretty_midi及原生JavaScript组成应用。CPU后端便于在普通设备或已有服务器试用，无需训练GPU或第三方模型API密钥。Linux环境已实测，Windows部署说明已写，用户Windows机器尚未验证。

## 三、自主实现与创新边界

自主实现包括校对界面与状态管理、原音定位、原始结果留存、修改历史、参考差异与自动定位模块、MusicXML量化导出、实验与打包工具。

Basic Pitch模型、推理与基础音符解码属于上游工作。短音/弱音提示是试听优先规则，MIDI力度不是模型置信度。音符编辑、MusicXML和序列对齐都有既有方法，不能仅凭组合宣称首创。

候选创新主张为：将琵琶短录音中的听音校对、参考旋律定位与后续制谱连接，减少从模型结果到可用乐谱的整理负担。当前已实现可操作流程；差异化与效率优势尚需同任务竞品比较和真实使用数据支持。

## 四、核心功能与算法

### 4.1 音符校对与可追溯记录

保留不可被编辑覆盖的模型初稿。当前音符可修改音高、起止时间、力度，可补音、删除、撤销。保存时校验音高范围、唯一编号、音符区间与版本冲突。原始MIDI、当前MIDI与JSON分别导出，区分模型输出与人工贡献。

### 4.2 手动参考对齐与差异

导入对应片段MIDI，支持最多500音符、1MB、120秒参考范围。时间映射为 t'=s×t+b。用户确认第一音位置及速度后，在时间窗口内一对一配对，先最大化可配对数量，再优先同音高，最后比较起音距离。

默认配对窗口0.3秒、起音容差0.08秒、时长容差0.12秒，均为可调整的原型设置。音高、起音、时长、参考有当前无、当前有参考无分别提示。超出范围的参考明确计为未比较，不静默丢弃。

### 4.3 单旋律自动定位（试验）

支持2—100个非重叠参考旋律音。将原始模型音符按相近起音组成候选组，以半全局动态规划匹配参考音符序列；允许前缀、尾部录音及多余音符，保留八度差异候选。目标是找到片段位置，不是证明音符正确。

递推采用匹配、跳过参考、跳过录音三种操作。匹配代价同音高为0，八度差为0.45，其他音高为0.7+min(半音差,12)/24；跳过参考代价0.9，跳过候选组代价0.18。这些参数未在独立琵琶验证集上校准，不是概率。

得到的候选锚点构成分段线性时间映射，使局部速度变化可被表示。只比较已定位的片段，其他录音音符明确列为未比较。相似重复段落标记为位置歧义；匹配线索不足或多声部参考时拒绝自动对齐并保留手动路径。

自动锚点来源于模型初稿，因此不独立。此模式明确不评定起音和时长，结果写为“未评定”，避免将对齐后趋近零的差异误报为高准确率。再次手动更新会退出自动模式。自动对齐不改写音符或录音。

### 4.4 乐谱草稿导出

用户指定四分音符BPM、2/4、3/4、4/4或6/8拍号和起拍位置。将音符量化到用户选择的十六分或八分三连音网格，填补休止、分配重叠声部、拆分长音与跨小节连音。MusicXML内记录导出设置，MIDI与原始秒级时间不被量化覆盖。

当前支持网页五线谱预览和手选三连音网格；不支持自动拍号/三连音识别、混合节奏推断、自由节奏完整记谱或琵琶技法标记；草稿需在制谱软件中确认。MuseScore在参赛者Windows设备上的打开与排版效果尚待实测。

## 五、开发、测试与实验

### 5.1 软件验证

56项完整测试通过，覆盖真实ONNX推理、编辑/持久化/撤销、MIDI与MusicXML、非法输入、版本冲突、数据校验、批量失败保存、参考差异、多声部配对与自动定位。

Chromium完整界面流程通过，包含上传、识别、编辑、下载、恢复、参考导入/对齐/定位与手机布局。独立music21解析验证MusicXML文件，包含多声部和连音回读。上述属于功能验证，不是用户试用或琵琶准确率。

### 5.2 公开吉他数据诊断

官方GuitarSet v1.1.0音频和JAMS归档经官方MD5校验。预先固定12段诊断，另12段本地不重叠后续验证；基础模型训练是否用过相同样本尚未核实，不能称为完全未见测试集。

|样本与指标|实测值|
|---|---|
|诊断12段：音高+起音F1宏平均|0.7975|
|诊断12段：音高+起音+结束F1宏平均|0.5660|
|后续12段：音高+起音F1宏平均|0.7611|
|后续12段：音高+起音+结束F1宏平均|0.5722|

起音容差50毫秒、音高50音分，结束容差取50毫秒或参考时长20%的较大者。实验文件含固定选择方案、逐段结果、源文件SHA256和失败记录。五组frame阈值实验没有超过默认方案，保持默认0.3，不声称模型提升。吉他结果不能代替琵琶结果。

### 5.3 真实琵琶诊断

用户本人演奏录制《春雨》《新翻羽调绿腰》《彝族舞曲》，确认均从所给谱页开头开始。三段统一取前30秒，模型分别输出77、130、114个音符，三段均可在界面校对。没有独立音符标注，不计算准确率。

《春雨》开头两小节的8音旋律提纲由谱面数字整理，八度暂定、时值采用等长示意，明确不是正式参考。自动定位得到约1.52—10.04秒的候选范围，保留一处D5/D4八度差异与额外音符线索。该结果来自同一模型的音符序列，不能用来给模型自身评分，也不能认定用户弹错。

## 六、部署与使用

运行方式及版本锁定见README和requirements.lock。单worker默认仅监听本机，服务器使用SSH转发或认证反向代理。此原型没有账号权限或完善的多用户资源隔离，不作为公共上传服务。

录音在当前服务处理，不上传到第三方模型API；项目文件保存在本地var目录，可删除录音与记录。源码包不含用户录音、私有项目、虚拟环境或实验大文件。

## 七、应用价值验证计划

固定任务终点为识谱者认可、可继续制谱的草稿。对比同一模型直接MIDI导出后编辑与本原型校对流程，统一音频、质量要求和制谱软件，交替任务顺序，分别记录准备、校对、排版耗时和最终错误。

独立标注应来自曲谱与听音核对，不能由本模型或自动对齐结果充当真值。真实学习者错音样本与“正确演奏”分别验证；样本少时仅报告个案，不宣称显著提效或推广到全部用户。此项尚未完成。

## 八、总结与展望

已形成音频识别、原音校对、参考定位、可追溯记录与乐谱草稿导出的完整原型，验证了三段真实琵琶输入与小片段定位。当前最主要缺口是独立标注、技法解释、真实用户对比和Windows/MuseScore验证。

后续优先核对原谱与实际演奏，建立小规模合法样本集，检查泛音/轮指造成的候选差异；再评估局部节奏与多声部对齐。没有实验支持前，不宣称琵琶专用高精度模型或新的纠错算法。
