# 答辩提纲（8页工作草案）

所有“待补”完成后再导出最终PDF。使用组委会要求；全篇匿名，不出现学校和指导教师。

1. **作品与任务**：谱易改；赛题AI+软件创新；单乐器短录音转谱校对。
2. **用户与需求**：真实访谈/使用场景待补；明确为什么用户需要可编辑乐谱草稿或音符记录。
3. **现有方案与差异**：Basic Pitch网页版、NeuralNote等实际对比待补；不把已有功能写为首次提出。
4. **系统架构**：音频解码→ONNX模型→人工校对→可追溯导出；标出开源模块与自研应用模块。
5. **核心演示**：真实琵琶输入、实际错音定位、校对、导出；截图待补。
6. **测试与验证**：后端14项已通过；浏览器以实际记录为准；琵琶原始与人工校对结果、耗时待补。
7. **应用价值与部署**：实际反馈待补；CPU运行、受控访问、Windows操作；不得虚构市场规模和用户量。
8. **总结与边界**：当前贡献、AI辅助开发披露、开源引用；滑音/轮指/排版等已知限制及下一步。

常见问答准备：模型是不是自己训练的？不是。创新如何证明？需同类对比和真实使用证据，目前待验证。校对后指标上升是不是算法改进？不是，是人工参与后的产品结果。用户为什么不用现成插件？必须用具体场景和实测回答，不能泛泛宣称更好。参赛者做了什么？按实际需求、设计、开发参与、测试与改进记录回答。
