# 创新与评分证据规划

暂定赛题2“AI+软件创新”。创新得分仍是薄弱项，不能以已实现的功能数量推断高分。琵琶试用者可以联系；已有用户本人演奏录制的三段音频和对应谱页，三段前30秒功能诊断完成，独立标注与实际用户任务对比尚未完成。

## 当前可如实说明的自主实现

- 原音、模型初稿与人工编辑结果对照；逐音符定位、补音、删除和撤销。
- 参考MIDI时间对齐与叠加、音高/起音/时长/缺失/新增差异、原音定位；保持演奏差异与识别错误的解释边界。
- 原始音符保持不变，逐次修改记录可追溯，分别导出原始与人工结果。
- 用户指定速度、拍号和起拍位置后，十六分音符量化成MusicXML草稿；跨小节延音拆分并加连音，重叠音符分配声部，空隙保留休止。
- 真实公开数据评测、失败保留与边界说明。

上述是软件工程贡献。基础模型、算法精度与音符解码来自Basic Pitch。MusicXML量化、编辑与留痕都有已有实现，不能仅凭组合宣称首创或独特壁垒。当前规则提示也不是经验证的错误检测算法。

## 候选创新主张：需要验证后才使用

围绕琵琶学习中的短录音校对，连接“听原音找问题—修音符—导出可继续制谱的草稿”，降低从识别结果到可用谱面的整理负担。

成立需要三类证据：

1. 需求：真实学习者/识谱者是否确有这个任务，现有流程的具体困难是什么。
2. 差异：相同任务下，与基础模型直接输出MIDI和至少一种现有编辑流程逐项比较；不能把竞品已有功能称为独有。
3. 效果：固定质量要求的任务完成率、耗时、音高和节奏错误；同时提供困难样本与用户负面反馈。

若没有差异或效果，改写为一般独奏转谱校对原型，不强行包装“琵琶专用”“创新算法”。
