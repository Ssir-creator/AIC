# 琵琶短录音试用指南

目标：验证“AI初稿→原音定位→人工校对→乐谱草稿导出”能否帮助懂谱的使用者完成任务。先完成真实试用，再决定是否以琵琶练习作为参赛定位。没有数据前不宣称提高准确率或节省时间。

## 今天准备

1. 联系一位懂琵琶或识谱的人，说明这是比赛原型试用，征得其同意。只记录匿名编号，不在提交材料出现学校、老师姓名或联系方式。
2. 自行演奏或使用有明确授权的短曲。提交音频的使用权与曲谱的使用权分别确认；不使用来源不明的商业录音。WAV优先，10—30秒，无伴奏、无背景人声。
3. 首段选择慢速、固定速度、清晰单音，记录曲名/匿名片段名、速度、拍号、起拍时间。另录一段含滑音或轮指的片段，作为困难案例，保留失败结果。
4. 请识谱者先根据原谱和听音独立整理音高与时间标注，保存CSV（pitch,start,end）。不要先把模型输出给标注者看。谱面反映预期音符、录音反映实际演奏，两者不一致时需要听音确认。

## 第一次试用：先确认能否完成任务

从开发包解压后按README运行，在浏览器上传录音。

- 看音符时间轴和模型初稿轮廓；点选音符，听原音片段。
- 修改错音、漏音、重复音和结束时间。短音/弱音只是检查提示，保留装饰音须由人判断。
- 导出原始MIDI、校对后MIDI和校对记录JSON。
- 在“导出乐谱草稿”填写四分音符BPM、拍号、起拍位置；导出两份MusicXML。
- 用MuseScore打开MusicXML，确认小节、节奏、声部和连音。6/8的BPM仍以四分音符为单位，不是附点四分音符。自由节奏和三连音不在当前量化支持范围内。
- 乐谱草稿固定十六分音符网格，会改变显示节奏；不会改变MIDI和原始时间。最终排版及琵琶技法标记仍需在制谱软件里处理。

请保留软件错误和不好用的地方，不只记录好评。Windows运行与MuseScore实际导入尚待用户设备验证。

## 第二次试用：比较完整任务耗时

任务终点统一为：识谱者认为主要音高、节奏正确，且能在MuseScore打开的乐谱草稿。不能只比较“一键识别耗时”。

- 方法A：同一Basic Pitch基础模型输出MIDI，在常用编辑/制谱软件中听音校对并整理乐谱。
- 方法B：本原型听音校对，按相同速度和拍号导出MusicXML，再在同一制谱软件确认。
- 至少准备两个难度接近的片段，先A后B与先B后A交替进行。只有一位试用者时，仍需明确存在熟悉效应，不能将结果推广到全部用户。
- 两种方法提供相同音频、曲谱、速度与任务说明；记录熟悉工具的练习时间。截图或屏幕录像中的时钟帮助复核计时。
- 分别记录准备、校对、排版确认时间，总耗时与最终质量同时报告；较快但错误更多不能描述成提升。
- 优先记录单次任务原始结果。样本少时只写“小规模试用”，不写显著性结论。

CSV模板见“琵琶试用记录模板.csv”。真实用户意见请保留原话、匿名编号和日期。匿名授权证明单独保存。

## 标注与评测

将校对记录和独立标注传回，运行：

```bash
.venv/bin/python scripts/evaluate.py review-record.json gold.csv --output artifacts/pipa-evaluation.json
```

这评测的是音符时间，不是MusicXML量化节奏。模型初稿与人工校对分开报告；不能将人工修改后的提升写成基础模型自身的提升。MusicXML需要另行比较节奏、小节、可导入性与可读性。

## 需交回的最小文件

- 两段有权使用的短音频、对应曲谱或独立标注；实际BPM、拍号与起拍位置。
- 至少一份真实试用记录CSV、校对记录JSON和用户原话。
- MusicXML是否能在你的MuseScore版本打开，有问题时保留错误截图。

录音无需压缩成大型数据包。首次只做一段也可以，实际完成多少就报告多少。


## 参考纠谱模块试用

由识谱者将练习片段整理为正确MIDI，先按原音演奏速度估计时序。参考必须来自独立曲谱和人工判断，不能直接把本模型输出当成参考。

导入参考后，用原音播放器停在第一音位置，点击“以原音当前位置对齐参考第一音”；再按末尾位置调整时间缩放。将音高、起音与时长提示逐项听音确认，并记录是否实际属于演奏问题、识别问题或对齐问题。自由速度段请缩短到少量小节，当前提供试验性参考旋律定位，但其模型起音不作独立时间标注。

当前曲谱输入支持MIDI，不支持简谱图片自动识别。你提供的三首曲谱图片用于人工整理参考，不会自动当作已标注真值。只写“正确版”的录音也不能直接作为逐音符准确率评测的独立标注。

## 简化独立核对包

解压“谱易改-独立听音核对包.zip”，用Edge/Chrome打开“打开这个页面.html”。无需应用服务；它内含三段本人录音，只显示原音，不展示模型建议。云端Chromium的file页面被环境策略限制，本次通过载入相同HTML内容验证播放波形、保存恢复和导出保护；Windows实际双击仍待设备验证。

核对者先检查春雨开头一小段，记录实际音高和起止；不确定就保留待确认。填写实际核对范围，不默认已经检查全部30秒。保存JSON即可交回，不用手写CSV；只有独立且完整核对声明和全部确认音符才允许导出CSV。人对标注的确认仍需复核，尤其50毫秒时间容差。

开发者用scripts/evaluate_independent_review.py评测配套确认JSON，必须核验核对记录、原音及模型记录的SHA256一致，再按同一核对范围统计。边界结束时间截断单列，较早起音不评定。旧版记录没有原音摘要时需重新上传对应原音生成记录；不能仅凭曲名相同强行评测。
