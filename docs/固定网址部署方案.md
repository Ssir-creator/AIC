# 固定网址部署方案 / 待确定托管环境

参赛者已选择在线完整版：固定网址、服务器更新后刷新访问，同时保留离线版。当前未取得服务器操作入口或托管平台，尚未上线，不能生成一个实际上不存在的固定网址。

## 已准备的服务器方案

Dockerfile提供Python3.12、ffmpeg、锁定依赖和官方ONNX CPU后端。容器只运行一个工作进程。镜像构建仅复制程序和依赖许可，不包含本人录音、现有项目、浏览预览包或密钥。

deploy/compose.yaml用于有Docker的独立服务器。应用端口仅供内部反向代理访问；Caddy入口提供HTTPS和登录保护，必须配置实际域名、登录名及密码摘要。项目录音和修改记录使用持久卷；普通重建/重启不删除项目数据。更新不能执行docker compose down -v。

这仍是受保护的单人工作站，不是多账号隔离平台。登录者可访问此服务的项目；未授权访问不能查看录音或操作接口。

## 上线前实际步骤

确认托管平台/服务器、管理入口和域名条件后，选择适配的部署路径。密码、私钥和平台令牌通过服务商安全入口或环境设置提供，不贴在聊天中。

有现有服务器时，再检查Docker可用性、80/443端口及已有网站配置，避免覆盖其他项目；已有反向代理时优先接入现有代理，不直接运行占用端口的新代理。域名DNS需指向实际服务器。模板不是未经检查即可套用的已上线配置。

服务构建、启动后，验证未登录访问被拒绝、本人登录后可上传/编辑/预览/导出，以及服务重启后项目保留。检查完成后才把真实固定网址交给参赛者。

## 更新方式

服务器代码更新并部署后，参赛者刷新同一网址即可。部署需要每次确实执行，不能把云工作区文件修改说成线上已经更新。可在选定平台后配置Git自动部署；目前没有设置自动部署或推送代码。
